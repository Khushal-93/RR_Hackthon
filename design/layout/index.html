1. Site Map & User Journeys

The information architecture is optimized for two core paths: Competition Judges validating integrity and evidence first, and Analysts/Scouts seeking rapid player lookup and head-to-head comparison.

Global Site Map Hierarchy
PRESSURE XI (Root)
└── 1. Overview (Dashboard) — Executive summary, Top 10 batters/bowlers, leverage by over, limits banner
└── 2. Rankings — Full roster table, forest plot, role toggle, filters, scatter plot, CSV download
└── 3. Player Profile — Deep dive dossier, component breakdown, stability check, match log
└── 4. Compare — 2-to-4 player picker, radar/bars, head-to-head probability, tie alert, side-by-side specs
└── 5. Pressure Explorer — Leverage definition, WP match explorer, dual over × wicket heatmaps
└── 6. Method & Reliability — 6-stage pipeline, WP calibration curve, out-of-time test table, graveyard, downloads
Primary User Journeys
Journey 1: Overview → Player Profile (Scout / Fast Lookup)
1. Lands on Overview → 2. Scans Top-10 Leaderboard → 3. Clicks high-performing player (e.g. Sudharsan / Bumrah) → 4. Arrives on Player Profile → 5. Reviews rating interpretation, Leave-2-Out check & match strip
Journey 2: Overview → Method & Reliability (Judge / Audit Verification)
1. Lands on Overview → 2. Reads Honest-Limits Caveat Banner → 3. Clicks "Read Full Methodology & Reliability Audit" → 4. Arrives on Method page → 5. Inspects Out-of-Time table (rho=0.25 batters, rho=0.29 bowlers) & dropped metrics cemetery
Journey 3: Rankings → Filter & Sort → Player Profile (Analyst Deep Dive)
1. Clicks Rankings in Top Nav → 2. Selects role (Bowlers), sets min balls (250+), filters Spinners → 3. Sorts table by Shrunk Rating or P(top-10) → 4. Clicks player name row → 5. Inspects individual phase breakdown and opposition mix
Journey 4: Rankings → Compare (Head-to-Head Evaluation)
1. On Rankings or Profile page → 2. Clicks "Compare This Player" or navigates to /compare → 3. Selects 2-4 peers in picker (e.g. Klaasen vs Pooran) → 4. Evaluates Pairwise Probability Matrix & reads Statistical Tie status → 5. Inspects component overlay
Journey 5: Global Search → Player Profile (Instant Any-Page Navigation)
1. Focuses Global Search input in Top Nav (hotkey /) → 2. Types player name → 3. Selects from auto-suggest list showing role, shrunk rating & balls → 4. Directly routed to Player Profile

5. Content Priority & Accessibility (Layout Level)

Landmark Regions & Heading Hierarchy

Every wireframe adheres to semantic HTML5 landmarks and strict single-h1 heading progression to guarantee zero screen-reader confusion.

  • Landmark Regions: Each page contains exactly one <header role="banner">, one <nav role="navigation">, one <main role="main">, multiple distinct <section aria-labelledby="..."> blocks, and one <footer role="contentinfo">.
  • Heading Hierarchy: <h1> is reserved strictly for the primary page title (e.g. "Who Delivers Under Pressure? IPL & T20I, 2022 to 2026"). Each major layout section uses an <h2> (e.g. "Leaderboards", "Empirical Findings", "Out-of-Time Repeatability"). Sub-components and cards use <h3>. No skipped levels.
  • Logical Tab Order: Global Caveat Tag → Nav Links → Global Search → Page Main Actions (Filters/Toggles) → Interactive Data Cards → Chart Data Table Toggles → Table Rows → Footer Links.

6. Open Questions & Ambiguities for Visual / Production Phase

To maintain strict adherence to instructions without guessing, the following structural decisions are surfaced for explicit user confirmation prior to visual design and Next.js frontend coding:

  1. Compare Page Picker Capacity: The wireframe implements a flexible 2 to 4 player picker. Do judges/analysts prefer capping at exactly 2 for clean head-to-head odds (e.g. "A beats B 64% of the time"), or allowing up to 4 with a pairwise probability matrix?
  2. Rankings Table Mobile Presentation: We have wireframed a responsive card-transform view (showing rank, player, rating, 80% CI and tier) with a "View Full 13-Column Scrollable Table" button. Should mobile default to the card view or horizontal swipeable table?
  3. Leave-Top-2-Matches-Out Sensitivity Warning Threshold: On the Player Profile, a warning badge triggers if dropping a player's top 2 matches causes a rating drop greater than 0.10 runs/ball or a rank drop of >10 spots. Is 0.10 the preferred threshold, or should it be pegged to the player's 80% credible interval width?
  4. Scatter Plot Zoom / Pan on Mobile: With 118 batters and 125 bowlers, plotting all points on a 360px mobile screen becomes dense. Should mobile scatter show only the Top-20 with a toggle to load all, or rely on touch pinch-to-zoom?
  5. Filter Drawer vs Accordion on Tablet: At the 768px tablet breakpoint, the filter toolbar wraps to 2 rows. Would the user prefer a collapsible drawer button (matching mobile) to preserve vertical chart space on tablets?
